Le stack tech de Discord en 2026

Stack temps-réel hybride Elixir + Rust + Python. Elixir/Erlang OTP porte le fanout messages ; Rust remplace progressivement Go et Elixir sur les chemins chauds ; Python reste sur l'API historique. Messages stockés dans ScyllaDB (migré depuis Cassandra en 2022), infra sur Google Cloud + Kubernetes.

Révisé 2026-07 Fondé 2015 · San Francisco, USA (majoritairement remote — bureaux SF, NYC, Amsterdam) 6 catégories · 18 composants
📈 Échelle (signaux publics)Plus de 200 millions d'utilisateurs actifs mensuels revendiqués publiquement, ~19+ millions de serveurs actifs par semaine, et un pic historique documenté à 11+ millions d'utilisateurs concurrents sur une seule bibliothèque Elixir (2019).

🧱 Stack technique (sourcé public)

▸ Backend temps-réel
Elixir + Erlang OTP actuel

Gateway WebSocket + fanout des messages — cœur temps-réel qui pousse chaque message aux bons destinataires. Post viral 2017 sur la mise à l'échelle à 5M+ d'utilisateurs concurrents.

depuis ~2016 · vu 2025 · 📝 Discord Engineering — How Discord Scaled Elixir to 5,000,000 Concurrent Users (2017)
Rust (NIFs Elixir + services hot-path) actuel

NIFs Rust intégrées dans les nœuds Elixir pour éviter les goulots BEAM sur le tri des membres — cité par Discord comme la clé pour tenir 11M+ d'utilisateurs concurrents sur un serveur unique.

depuis 2019 · vu 2025 · 📝 Discord Engineering — Using Rust to Scale Elixir for 11 Million Concurrent Users (2019)
Rust (Read States, remplacement Go) migration entrante

Service 'Read States' (l'état lu/non-lu par utilisateur, milliards de req/jour) réécrit de Go vers Rust en 2020 — motif public : les GC pauses Go étaient inacceptables au 99e percentile.

depuis 2020 · vu 2024 · 📝 Discord Engineering — Why Discord is switching from Go to Rust (2020)
Python (API historique + services internes) actuel

Stack Python d'origine — API monolithique historique et services outillage internes. Offres backend Python toujours publiées régulièrement.

depuis 2015 · vu 2025 · 💼 Discord Careers — offres Backend Python (signal stack public)
Go (services périphériques restants) migration sortante

Reste utilisé pour certains services périphériques mais les chemins hot ont majoritairement basculé vers Rust ou Elixir depuis 2020.

depuis ~2017 · vu 2024 · 📝 Discord Engineering — Why Discord is switching from Go to Rust (contexte)
▸ Data store
ScyllaDB migration entrante

Store principal des messages depuis la migration 2022 — trillions de messages migrés depuis Cassandra en visant des tail latencies P99 nettement plus basses.

Store historique des messages — objet du célèbre post 2017 'How Discord Stores Billions of Messages', remplacé par ScyllaDB en 2022 pour les problèmes de compaction et de garbage collection JVM.

🏛️ Culture ingénierie

Discord fait partie des entreprises les plus prolifiques en engineering blogging depuis 2017 — posts longs, chiffrés, avec vraie post-mortem style (le post 'Why we're switching from Go to Rust' cite les GC pauses Go au P99, celui sur ScyllaDB cite les compactions Cassandra JVM). Le pattern récurrent : partir d'un langage 'assez bon' (Go, Cassandra, MongoDB, React Native) puis migrer vers un choix plus optimisé (Rust, ScyllaDB, natif mobile) une fois la contrainte comprise. Culture 'small teams, big impact' revendiquée dans les offres publiques ; entreprise remote-first depuis la pandémie.

👋 Recrutement

Recrutement remote-first majoritairement US + certains pays européens (offres 'remote in select countries' publiées). Process typique : screening RH → home assignment ou live coding selon rôle → panels (design système, culture) → onsite virtuel. Offres détaillées par stack : Backend Engineer (Elixir / Rust / Python), Platform Engineer (Kubernetes / GCP), Client Engineer (React / Electron / Native), Data / ML Engineer (Python / BigQuery). Page d'offres publique : discord.com/careers.
