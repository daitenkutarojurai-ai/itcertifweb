Comment lire ça

Chaque carte = un provider. Le grand chiffre = coût mensuel total en USD pour ton workload. Le breakdown détaille compute / stockage / egress / object. La carte verte avec badge CHEAPEST = le provider le moins cher pour ces paramètres.

Méthodologie (à lire avant de t'enflammer)

  • List price, on-demand. Aucune réduction RI / Savings Plan / CUD / SUD. Les rates réels en production peuvent être 30-50% en dessous.
  • vCPU/RAM linéarisé. Chaque provider a une famille d'instances de référence (cf. sku dans data/infracost/<provider>.json). La conversion "1 vCPU = $X / mois" est une moyenne sur la gamme, pas un prix instance par instance.
  • Egress. Modélisé comme tier gratuit + prix au GB. R2 = egress zéro, ce qui change tout pour les workloads de diffusion.
  • EUR → USD pour Hetzner. Conversion 1 EUR = 1.08 USD (mai 2026, BCE). Les chiffres affichés sont en USD pour la comparaison.
  • Cloudflare R2 = storage-only. Le compute Workers est facturé par requête, pas par vCPU — pas mappable ici. On affiche "—" et on garde la ligne pour montrer le coût storage réel.
  • Dernière révision affichée par provider. Les tarifs cloud bougent. Si la pill dit "> 6 mois", recoupe avec la page officielle.

Pourquoi pas une API live ?

AWS expose un pricing API (lourd, JSON 100+ MB), GCP/Hetzner/Fly.io non. Pour rester 100% client-side et instantané on cache les valeurs en JSON dans le repo et on bump à la main. Plan : une Cloudflare Pages Function qui fetch le pricing AWS une fois / jour (P2 backlog).
