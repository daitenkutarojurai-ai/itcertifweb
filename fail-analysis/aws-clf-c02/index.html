⚠️ Fail Analysis

Pourquoi les gens ratent AWS Cloud Practitioner (CLF-C02)

Le CLF-C02 est souvent sous-estimé. Parce que c'est un examen de fondation, les candidats pensent qu'un survol suffit. Résultat : ils arrivent à l'examen sans maîtriser l'étendue réelle du catalogue AWS (200+ services), piègent sur les questions de pricing, et plantent sur le Well-Architected Framework. Les 5 erreurs ci-dessous couvrent 90% des cas d'échec — sourcées depuis r/AWSCertifications et AWS re:Post.

Révisé 2026-05 AWS ne publie pas de taux officiel. Estimations communautaires : ~80% en première tentative pour les candidats qui ont révisé. Piège : l'exam semble 'facile' — beaucoup sous-révisent.
TL;DRLe CLF-C02 couvre TOUT le catalogue AWS en surface. Ceux qui ratent ont appris 20 services en profondeur et ignoré les 50 suivants. La largeur bat la profondeur ici.

Top 5 erreurs (du plus fréquent au moins fréquent)

#1
Se concentrer sur 15-20 services en profondeur au lieu de couvrir la largeur.
Cause #1 citée dans les posts d'échec sur r/AWSCertifications.

Le CLF-C02 teste la connaissance de QUAND utiliser chaque service, pas comment le configurer. Si tu maîtrises EC2, S3 et RDS mais ignores SQS, SNS, CloudFormation, CloudWatch, IAM, Cost Explorer, Trusted Advisor, et 30 autres — tu vas planter les questions 'choisir le meilleur service pour ce scénario'.

Le fixFais un tour systématique des catégories du blueprint officiel : Compute, Storage, DB, Networking, Security, Monitoring, ML, Management & Governance, Developer Tools, Pricing. 2-3 phrases par service suffisent pour l'exam — pas besoin de configurer quoi que ce soit.
#2
Ne pas comprendre les modèles de tarification AWS.
~35% des posts d'échec mentionnent des questions pricing ratées.

On-Demand, Reserved Instances (1 an vs 3 ans, No Upfront vs Partial vs All), Savings Plans, Spot, Dedicated Hosts — l'exam teste des scénarios précis ('débit prévisible sur 3 ans : quel modèle ?', 'workload interruptible : quel modèle ?'). Sans comprendre les compromis, tu devines.

Le fixApprends les 5 modèles de pricing EC2 + les 2 types de Savings Plans en mode tableau comparatif. Règle d'or : Spot = workload flexible/interruptible, Reserved = prévisible et long terme, On-Demand = imprévisible ou court terme.
#3
Confondre les services de stockage S3, EBS, EFS et FSx.
Erreur classique sur les questions 'quel service de stockage pour ce cas d'usage'.

S3 (objet, web), EBS (bloc, attaché à une instance EC2), EFS (fichier partagé, Linux multi-AZ), FSx for Windows (partage Windows) — l'examen adore proposer 2 réponses plausibles dans la même famille. Sans connaître les différences clés (accès objet vs bloc vs fichier, durabilité, cas d'usage), tu choisis mal.

Le fixMémorise une phrase pour chaque : S3 = site web ou backup d'objets ; EBS = disque dur d'une instance EC2 ; EFS = lecteur réseau partagé Linux ; FSx = partage réseau Windows. L'exam donne le contexte dans la question — lis-le attentivement.
#4
Ignorer le AWS Well-Architected Framework.
Présent dans ~25% des questions d'examen selon les retours communautaires.

Les 6 pilliers (Operational Excellence, Security, Reliability, Performance Efficiency, Cost Optimization, Sustainability) reviennent en permanence sous forme de 'Quelle pratique correspond à quel pilier ?' ou 'Ce scénario viole quel pilier ?'. Beaucoup ne le révisent pas car 'c'est de la théorie'.

Le fixRetiens les 6 pilliers + 1 service ou pratique emblématique par pillier. Ex : Reliability → Multi-AZ, Auto Scaling ; Security → IAM least privilege, MFA, KMS ; Cost Optimization → Reserved Instances, rightsizing.
#5
Confondre le modèle de responsabilité partagée.
Piège récurrent dans les questions sur la sécurité.

L'exam teste systématiquement 'qui est responsable de quoi dans le modèle partagé AWS'. AWS gère la sécurité DU cloud (infrastructure physique, hyperviseur, réseau). Le client gère la sécurité DANS le cloud (données, OS, patchs, IAM, chiffrement applicatif). Les questions sont souvent formulées pour piéger sur la frontière.

Le fixMémorise la règle : AWS = hardware, datacenters, hyperviseur, services managés. Toi = OS (si EC2), applications, données, IAM, chiffrement. Pour les services managés (RDS, Lambda), AWS gère plus — mais tu gardes la responsabilité de tes données et des permissions.

Évite ces 5 erreurs en t'entraînant correctement

La pratique sur des questions au format examen reste la méthode #1 pour calibrer son niveau. AWS Cloud Practitioner (CLF-C02) a sa propre banque sur CertQuests — gratuite et sans inscription.
