### Title/description length overflow — still growing, still flagged

- **146 titles > 60 chars** (Google SERP cutoff), up from 143 last week.
- **102 descriptions > 160 chars** (SERP cutoff), down from 109 last week
  (worst offender this run: `reality-check/saas-100k-mrr-12-mois/index.html`
  at 416 chars — pre-existing content page whose description is a full
  paragraph, not a summary).
- Worst offender title this run:
  `failbase/pires-decisions-startup-tech/index.html` at 100 chars.

Root cause is unchanged: every content generator in `scripts/gen-*.js`
appends `— CertQuests` (12 chars) to the raw pack/topic name, pushing titles
that were fine before the suffix over the 60-char threshold; the description
generators aren't length-clamped at all. As of this run 146 / 394 = **37%
of pages** overflow the title limit — this drift needs a generator-level
fix (cap raw title at 46 chars pre-suffix, cap description at 155 chars
post-truncate-at-word-boundary) rather than a per-file sweep. Not safe to
auto-truncate this run — risks mid-sentence cuts and losing keywords.

### Duplicate-content finding — auto-fixed (canonical + 301)

`d023933` created `news/vault-associate-002-2026/` covering
HashiCorp Vault Associate 002, but the same topic already lives at
`news/hashicorp-vault-associate-002-2026/` (shipped 2026-06-25, in
`sitemap.xml`, indexed for three weeks). Two live URLs for a single
article splits ranking signals and triggers Google's near-duplicate
consolidation heuristic — a real SEO regression.

Auto-fix applied — non-destructive: neither file deleted, no history
rewritten:

1. `news/vault-associate-002-2026/index.html` — `robots` meta flipped
   to `noindex, follow`; `<link rel="canonical">`, `og:url`, and
   JSON-LD `@id` all repointed to
   `https://certquests.com/news/hashicorp-vault-associate-002-2026/`.
2. `_redirects` — added two 301 rules so both
   `/news/vault-associate-002-2026/` and its trailing-slash-free
   variant redirect to the canonical URL on Cloudflare Pages.

Net effect: search engines consolidate onto the pre-existing URL, the
newer file remains available on disk (so nothing links-in breaks), and
no sitemap entry is added for the duplicate. Root cause is upstream —
the content-generator script (`news`-scheduled agent) doesn't check for
existing folders whose slug covers the same exam family before minting
a new one. Backlog item added.
